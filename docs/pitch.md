## 5-minute script

**1. The problem.** Chamber employees repeatedly hit the same questions —
approval thresholds, deadlines, which form is current — that already have
answers scattered across dozens of internal regulations. Experienced
colleagues end up as the real search engine. A wrong internal answer isn't
contained: an employee repeats it to a member, a company, or an authority, in
the chamber's name — so a confidently wrong answer costs more than an
unanswered question. Quote gathered on-site from MKIK's IT lead: *"Employees
rely on hallway rumors — even though there's a perfectly good procurement
policy."*

**2. Live demo — a supported question.** Ask a real question the corpus
covers, e.g. *"10 db irodai asztalt vennék, nettó 1,2 M Ft-ért. Elég 3
ajánlat?"* Show the answer, click the `[n]` citation, open the evidence
drawer, and let the jury read the exact clause and page for themselves before
trusting the answer.

**3. Live demo — deliberate abstention.** Ask something the corpus does not
cover (e.g. an HR/leave question against a procurement-only corpus). The
system must say *"A rendelkezésre álló dokumentumok alapján erre nincs
elegendő fedezet"* rather than guess. This is worth more to the jury than ten
successful answers — it's the core trust claim.

**4. The three numbers.**
- *Extensibility* — permissions, multi-chamber isolation, and connector
  ingestion are already designed-for extension points (`docs/architecture.md`),
  not rewrites.
- *Scaling* — the real 10× multiplier is chamber count (23 regional
  chambers), not document volume; see `docs/scaling.md`.
- *Cost* — ~1–12 Ft per question depending on local vs. cloud, ~8–26k
  Ft/month per chamber; see `docs/costs.md`.

**5. The chamber-sourced differentiator.** When the system abstains, it
doesn't just stop — it routes the employee to the actual responsible role
(e.g. "this is a procurement-value question — ask the finance manager"),
using the real approval chain from the regulation itself. This idea came
directly from on-site conversation with MKIK's leadership, not from the
original brief.

## What to avoid (per the brief, and it holds)

- Reading a feature list — the jury decides, doesn't take notes.
- Naming the tech stack as the argument. "Modern" isn't "good."
- A rehearsed, risk-free demo question. It shows, and it costs trust.

## Demo scenarios prepared

1. **Clean success** — direct question, single source, exact page + quote.
2. **Multi-source** — a question that needs two documents combined, both
   cited.
3. **Deliberate abstention** — out-of-corpus question, explicit refusal.

See `eval/benchmark.jsonl` for the underlying supported/ambiguous/unsupported
question set used to validate all three before presenting.
